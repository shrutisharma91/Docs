## 2. Engine contracts (lane 1) — `core/dashBuckets.ts`, `core/dashIndex.ts`, `core/plFigures.ts`

**`core/plFigures.ts` is DONE and frozen.** `plFigures(moveOf, stock)`, `plStock(inputs)`, `moveFromTotals(groups, ledgers, cid, totals)`.
`ProfitLoss` (`ui/reports.tsx`) and `RatioAnalysis` (`ui/reports/financial.tsx`) both call it; the placeholder line in the second is gone. Proven
three ways in `scripts/assert/plfigures.assert.ts` (legacy oracles verbatim, the goldens, a book worked by hand). The one deliberate difference
is the order in which Ratio Analysis' nett profit adds the indirect lines (now the statement's order): it can differ in the last bit of a double
and is asserted to print the same. **Do not edit this file**; if the statement's arithmetic must change, the goldens and the suite change first.
The Dashboard reads it through `plMoveOf(index)`.

**`core/dashBuckets.ts`** (signatures, one body done):
- `bucketsFor(from, to) -> BucketPlan` and `bucketIndex(plan, iso)`: **not implemented, lane 1**. Rule constants are in `BUCKET_RULE` (day to 31
  days, week to 120, month, quarter above 24 months), `MAX_BUCKETS` 400. Assert at the boundaries (one-day window, leap day, 31-day month, a
  year across a calendar year, exactly 31/32 and 120/121 days, 24/25 months); the plan covers the window exactly, clipped, no gap, no overlap.
- `asOn(period, today, mode)` and `asOnKind(...)`: **implemented in the scaffold** because the rule is fully specified and lane 3's foot dates need it from day one:
  `min(period.to, max(today, period.from))` under `'today'`, `period.to` under `'periodEnd'`. Asserted in `dash-scaffold.assert.ts`, including **C6**
  (equals `ageingAsOn(period.to, today)` whenever today is inside the window or the year is closed; a window wholly in the future is the one documented difference).
- `isFutureBucket(b, today)`: implemented.

**`core/dashIndex.ts`**: `DashIndexInputs`, the `DashIndex` shape (typed arrays: `open`, `atAsOn`, `dr`, `cr`, `byBucket`, `cashFlow`, `parties`,
`unreconciled`, `todayStats`, `stats`), `LEDGER_CLASSES` / `CLASS_SLUG` / `PL_SLUG_CLASS` / `CASH_CLASSES`, and **the read API the widgets use**
(`balanceOf`, `movementOf`, `plMoveOf`, `incomeByBucket`, `expenseByBucket`, `salesByBucket`, `purchasesByBucket`, `cashFlowSeries`, `ledgerBalances`,
`topLedgers`). Every function throws `not implemented` until lane 1 fills it. **Lane 3 calls only the accessors, never the arrays**, so lane 1 may
change the array layout freely. Obligations, each a test in `dashboard-v2.assert.ts` (lane 1's half): the index equals `closingBalances`,
`periodTotals`, `monthlyTrend` and `rankParties` at 2k, 50k, 250k and on the sample company, compared at paise; optional and non-posting vouchers
never reach it (`postsToLedgers` once per voucher); the cash net matches an independent per-voucher oracle and a Contra between two banks is zero;
`opening + in - out = closing`; buckets sum to the window figure; a bad window is an empty plan, never a throw.
Gaps lane 1 should close in the same file: a per-ledger balance read (`tdsPayable` and a Receivables-by-ledger need one: add `ledgerBalance(ix, id)`), and
the **stock cost** note in section 10.

Pure engines: no `src/ui`, `src/state`, React, Dexie. `scripts/perf` bundles these through `passes.dash.ts` and refuses an engine that imports any
of them; `dash-scaffold.assert.ts` scans the four files for the same imports.

## 3. Widget contracts (lane 3) — `ui/dash/widgets/types.ts`, `registry.ts`

A widget is two halves, kept apart so the catalogue can be listed, searched and gated without running anything:
- **`WidgetMeta`** (static, complete from the scaffold in `WIDGET_META`): id, label, blurb, aliases, gallery group, form, sizes, default size and
  default-on, `needs { right, feature?, partial? }`, `engine` passes, `clock`, `drill({cid}) -> Screen | null`, `since`.
- **`WidgetImpl`** (runtime, registered by each widget's file with `registerWidget`): `compute(env) -> data`, `isEmpty`, `empty`, `Render`.
  `Widget = WidgetMeta & WidgetImpl` is what the board draws.

Rules (each is a test or a probe): a widget the operator cannot open is **not drawn, not listed, not computed**; a widget not on the board is not
computed; `compute` is **pure** over `WidgetEnv` (no store, no `Date`, no storage: `env.today` is the clock, set again at local midnight);
`env.lazy.bills() / stock() / gst(period)` are memoised on array identity, built on first call and only for a visible widget, and a widget must list
the pass in `meta.engine` before calling it; a stacked Dashboard computes nothing (`useIsTop`); a throw shows "Could not work this out. Retry." in
the widget's own frame; **every figure equals the report its `drill` opens, on the same window and the same as-at** (a disagreement is a blocker).
Navigation goes through the board's drill helper, which calls `ui/navigate.ts requestNav`, so the nav-stack policy (dirty guard, no pile-up) applies.
`widgetVisible(meta, feats, ctx)` is declared and **not implemented** (lane 3; in the terms of `core/access.ts`).

The registry keeps the **shipped label and blurb of the fifteen shipped ids exactly** (the customise recipes and `dashboard-custom.assert.ts` name
them); changing one is a deliberate edit made with the behaviour behind it (the Latest vouchers fix, the GST words of D8) and the suites that pin it.
Three shipped tiles (`cash`, `receivables`, `payables`) become cards that keep a Small tile face. Order in the list is the default display order.

## 4. Chart contracts (lane 2) — `ui/dash/charts/types.ts` (+ stubs, barrel)

Props for `Columns`, `StackBar`, `RankBars`, `Sparkline` and `ChartFrame`, and the **table twin** shape (`TableTwin { caption, columns, rows }`): every figure a
tooltip shows is in the twin and nothing else is. The components exist as **stubs** (`Columns`, `StackBar`, `RankBars`, `Sparkline` draw nothing; `ChartFrame`
draws its children) so lane 3 compiles against them today; lane 2 replaces the bodies and keeps the props. Import from the barrel
`ui/dash/charts/index.ts` (it loads `styles/dashviz.css`; the light finish loads globally through `styles/light.css`).
Rules: `role="img"` + a one-sentence summary; marks in **one tab stop** (roving tabindex, Enter drills, Esc leaves); hit areas are the whole band; the kit never
navigates (`onDrill`); colour is never alone (a legend, a text label and an amount on every segment); series colour is **`--viz-1..4`** and the ageing ramp
`--viz-age-1..4` (new tokens in `src/styles.css`: a light-only value in the `:root[data-scheme='light']` block 5b and a dark override, validator output recorded
beside them, AA in both schemes; extend `visual.assert.ts`, never relax it); the existing `--tone-*` stay KPI stripe accents; a status colour is never a series
colour; no hex in components; text with `textContent`; text sizes in rem or tokens, never px and never an assumption about the root font size (the Settings window
changes theme, accent, font and size). `core/dashScale.ts` holds the signatures for the maths (`niceTicks`, `yOf`, `bandGeometry`, `labelFits`, `thinLabels`,
`axisInr`), import-free, bodies lane 2's.

## 5. Layout contract (lane 3) — `DashItemStored.cfg?`

`types.ts` now has `DashItemCfg = Record<string, unknown>` and `DashItemStored { id, on, size, cfg? }`. Nothing reads or writes it yet, and
**`resolveLayout` / `serialiseLayout` still DROP it** (the serialiser rebuilds `{id, on, size}`): that is the first job of lane 3 (**slice S0**), and it must land
**before anything stores a `cfg`** (the older-client lesson, contract C9, decision D10): both reader paths keep every item field, unknown extras included, on a
round trip: `pickLayout`/`resolveLayout` and `sanitisePersonalStore` (which re-serialises through `resolveLayout`). The suite extension: an item with `cfg` and with an
unknown field survives both paths, hostile `cfg` (a string, an array, a 1 MB object, `__proto__`) never throws and is dropped to `undefined` for the widget, a size
outside a widget's `sizes` falls back to its default. `master-resave.assert.ts` stays green untouched (it classifies `Company` keys; `cfg` is inside `Company.dashboard`).

## 10. Known gaps, risks and the deliberate behaviour changes (so none is slipped in)

1. **`cfg` is dropped by today's readers** (section 5): S0, first, before any stored `cfg`.
2. **The stock cost of the profit headline.** `plStock` calls `stockDelta`, which runs the inventory valuation (up to two `stockPositions` passes, 124 ms each at 250,000 vouchers) for a company with stock
   items; the Income and expense card and the Net profit tile therefore list `stock` among their passes. They cannot share the lazy `stock()` pass (different `upto` dates). Lanes 1 and 3 decide
   whether to share one valuation walk or accept the cost; whichever they pick, the budget (about 400 ms for everything at 250,000 vouchers) is re-measured and reported.
3. **Deliberate changes to pinned behaviour** (each moves a suite or a golden, named in the lane's gate output): the default board (twelve on, Quick Entry off; `dashboard-custom.assert.ts` rewritten, the pinned
   "the default IS the dashboard the app always drew" with it); balances stamped with the as-at date, not the period end (every tile's text; `dash-tiles*` re-recorded); the hero line stops saying "FY"
   for any period; the GST tile's words (D8); a stored size outside a widget's `sizes` falls back to its default (a saved `trend` at S reads L); the Latest vouchers list stops showing future-dated vouchers
   first (if the label changes, the recipes that name "Recent Vouchers" change with it).
4. **Receivables must add up**: Current + Overdue + Unapplied equals the headline, which equals the Sundry Debtors balance at the as-at date; a test fails if not. Without bill-wise the card shows the headline only.
5. **Perf harness rules**: a core file imported by `scripts/perf` may not import `src/ui`, `src/state` or Dexie; mirror rows move with the code; no super-linear regex anywhere (cap length before a pattern test).
6. **The company layout** is written by an administrator through the existing path (`C`); system writes never stamp the user; the dashboard writes nothing else.
7. **The `REPLACE-WITH-LISTQUERY` marker** (D12) is on every line of the bespoke Overdue list.
